## What Was Built

### 1. `netlify/functions/ebay-sync.js`
Daily sync function that pulls PAID orders from eBay Fulfillment API and upserts them into the `sales` Supabase table.

- **2 API calls only:** token refresh + orders fetch (no tracking, no finances)
- FVF calculated locally at 13.25% on `salePrice + shippingCharged`
- Lettermail orders ($2.00 ship cost) vs tracked ($5.50 Chit Chats) auto-detected via `shippingServiceCode`
- Upserts on `ebay_transaction_id` (unique per line item, not per order)
- Scheduled daily at 13:00 UTC via `netlify.toml`
- Protected by `SYNC_API_KEY` (stored in browser `localStorage` as `ygoexclusives_sync_key`)
- `?debug_env=1` endpoint (no auth) to verify env vars
- `?dry_run=1` to preview without writing to Supabase
- `?since=YYYY-MM-DD` for historical backfill

### 2. `ebay-auth.html` + `netlify/functions/ebay-auth-callback.js`
One-time OAuth helper to get a new eBay refresh token with correct scopes.

### 3. Sales tab UI (`js/sales.js` + `index.html`)
- `⟳ Sync eBay Sales` button + `▾` dropdown for date-ranged backfill
- Slide-in detail panel showing financials, buyer info, fulfillment
- `+ Log Sale` modal for manual entries (eBay, Facebook, In-Person, YGO Store channels)

### 4. Local debug scripts (not committed to git)
- `_test_ebay.js` — test token + raw order fetch
- `_test_sync.js` — full sync logic test locally  
- `_check_ebay_scopes.js` — generate OAuth auth URL with all scopes
- `_exchange_code.js` — exchange auth code for refresh token

## Issues Encountered & How They Were Solved

### Issue 1: `invalid_scope` on token refresh
**Symptom:** Token refresh returned `invalid_scope`  
**Root cause:** Refresh token was obtained with only `sell.item`/`sell.item.draft` scopes — not `sell.fulfillment`  
**Fix:** Built OAuth re-auth flow. Probed scopes via client_credentials (didn't work — seller scopes require user auth). Used `_check_ebay_scopes.js` to generate correct auth URL with all provisioned scopes. Exchanged code manually via `_exchange_code.js`.  
**Key learning:** Client credentials flow cannot test user-level `sell.*` scopes. Must use authorization code flow.

### Issue 2: Scope probe gave false negatives
**Symptom:** All `sell.*` scopes showed ✗ in client credentials test  
**Root cause:** Seller scopes require user authorization — they will always fail via `grant_type=client_credentials`  
**Fix:** Hardcoded the provisioned scope list from eBay Developer Portal into the auth URL instead of probing.

### Issue 3: Re-auth callback showed blank "Scopes granted"
**Symptom:** `ebay-auth-callback.js` success page showed empty scopes  
**Root cause:** eBay sometimes doesn't return `scope` field in authorization_code exchange response — this was cosmetic only, token was valid  
**Fix:** Confirmed token worked by testing with `_test_ebay.js`

### Issue 4: `Unexpected end of JSON input`
**Symptom:** Sync failed parsing empty API responses  
**Root cause:** Some eBay API responses return empty bodies; calling `.json()` directly throws  
**Fix:** Added `safeJson()` helper that reads `.text()` first and parses safely

### Issue 5: Finances API 404
**Symptom:** `fetchTransactions` returned 404  
**Root cause:** Finances API uses `apiz.ebay.com` not `api.ebay.com`  
**Fix:** One-line URL change. Later removed Finances API entirely — not needed for basic sales log.

### Issue 6: Sync returned 0 orders
**Symptom:** Sync succeeded but fetched 0 orders  
**Root cause:** Default window was 48h; most recent order's `lastModified` was 3 days ago  
**Fix:** Changed default window to 7 days. Added `▾` button for custom date backfill.

### Issue 7: `fetch failed` in Netlify function
**Symptom:** Function returned `{"error":"fetch failed"}` — no orders, no error details  
**Root cause:** Netlify was running an old Node version without global `fetch`  
**Fix:** Rewrote all HTTP calls using Node's built-in `https` module (no external dependencies, works on any Node version)

### Issue 8: Wrong SUPABASE_URL in Netlify (`.com` vs `.co`)
**Symptom:** `getaddrinfo ENOTFOUND xyhzwmlqmazloyerelas.supabase.com`  
**Fix:** Corrected to `.co`

### Issue 9: Stale SUPABASE_SERVICE_KEY in Netlify
**Symptom:** Supabase upsert returned 401 Invalid API key  
**Root cause:** Netlify had the old project's service key  
**Fix:** Used `npx netlify env:import .env` to sync all env vars from local `.env` file in one shot

### Issue 10: `#` in refresh token truncated during env import
**Symptom:** EBAY_REFRESH_TOKEN imported as `v^1.1` only  
**Root cause:** `#` is treated as comment delimiter in `.env` files  
**Fix:** Wrapped token value in double quotes in `.env`: `EBAY_REFRESH_TOKEN="v^1.1#..."`

### Issue 11: SYNC_API_KEY mismatch
**Symptom:** Function returned `{"error":"Unauthorized"}` even after key set in localStorage  
**Root cause:** Key in Netlify (43 chars) was different from key used in app (24 chars) — set at different times  
**Fix:** Read actual key from Netlify dashboard, set in localStorage via dev tools: `localStorage.setItem('ygoexclusives_sync_key', 'KEY')`

### Issue 12: FVF calculated on sale price only
**Symptom:** Net profit slightly overstated  
**Root cause:** eBay charges FVF on total received (sale + shipping), not sale price alone  
**Fix:** Changed `fvf = salePrice * 0.1325` to `fvf = (salePrice + shippingCharged) * 0.1325`

## Key Architecture Decisions

- **No Finances API** — FVF calculated at 13.25% locally. Simpler, faster, no extra scope needed. Can add real FVF later if eBay approves `sell.finances`.
- **`https` module not `fetch`** — Avoids Node version dependency. Works on Netlify regardless of runtime.
- **Upsert on `ebay_transaction_id`** — Unique per line item (not per order). Safe to re-run sync repeatedly.
- **Shipping cost by service:** `CA_PostLettermail` → $2.00, all others → $5.50 Chit Chats tracked
- **`netlify env:import .env`** — The right way to sync all Netlify env vars at once from local config. Requires `netlify link` first.
